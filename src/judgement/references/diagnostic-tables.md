# 诊断自检表（六份·完整可填版）

> 本文件配合本专家正文使用。用户要动手自查、要打印填表、要把表发给团队时，用这一份。
> 正文只保留填法与纪律，完整表格在这里——避免同一张表在正文与附件各存一份。
> 一至三份是通用表（任何体量都可用）；第四份按组织体量裁剪，第五份供大体系先用，第六份是轻量档的最小台账表头。

---

## 一、六环自检表（可直接填的诊断表）

**填法**：逐环回答"有动作吗 / 有责任人吗 / 有人回头看吗 / 结论送回上一环了吗"，答不上来的那一格就是断点。

| 环 | 有动作吗 | 有责任人吗 | 有人"回头看"吗 | 结论送回上一环了吗 | 你的填写 |
|---|---|---|---|---|---|
| 发现 | 只看投诉，还是也看没开口的人？ | 谁负责把信号找全？ | 有没有定期盘"漏没漏"？ | 发现的问题，回流到定位了吗？ | |
| 定位 | 有没有从现象下钻到可改的一层？ | 谁负责定根因？ | 定位错了有人复核吗？ | 定出的动作，进派单了吗？ | |
| 派单 | 机器与人的分工清楚吗？ | 有没有明确的主？ | 绕圈单有人看吗？ | 派单的责任与时效，进处理了吗？ | |
| 处理 | 客户诉求线与内部责任线对齐了吗？ | 谁对"真解决"负责？ | 分层干预做了吗？ | 处理结果，进验证了吗？ | |
| 验证 | 有没有回头核客户感知？ | 谁负责验证？ | 指标是否同向？ | 验证结论，进评估了吗？ | |
| 评估 | 有没有做对照组？ | 谁负责下结论？ | 结论是否被检验过？ | 结论，送回发现了吗？ | |

**判读**：多数组织的断点不在"有动作"列，而在**"有人回头看"**这两列——有动作、有责任人都能填，回头与回流往往是空的。先补"回头看"，比补流程节点便宜得多。

---

## 二、四类能力自检表（找短板用）

上一张表找的是"断在哪一环"，这张表找的是"哪类能力最弱"。

**填法**：每类能力选一个最接近的档位，然后看最弱的那一档。

| 能力 | 低（出事才动） | 中（能跑能验） | 高（自我校准） | 该补的信号 | 你的档位 |
|---|---|---|---|---|---|
| 全面感知 | 只看投诉，无主动测量 | 三类指标分开看、双通道在跑 | 异常自动成单、阈值自动收敛 | 看板没人看、异常没有出口 | |
| 智能研判 | 从不主动识别 | 有清单、有专题、有对照 | 标签动态迭代、进入策略 | 有评分无清单、清单无动作 | |
| 高效处置 | 一刀切、无分层 | 分层标签、分档配策略 | 效果回流、策略自动加权 | 只考核覆盖率、无对照 | |
| 有效评估 | 只写总结报告 | 口径前置、三类同框 | 结论直接决定资源分配 | 只报一类、结论不落决定 | |

**判读纪律**：

1. **锚行为，不锚形容词。** 判据是"能不能举例"——说"低"就要举得出"从来没主动监测过"。举不出例子的等级判断，就是自我感觉。
2. **看最弱的一档，别看平均。** 四类能力里最弱的那一类，决定了闭环整体的下限——补短板比堆长板便宜得多。
3. **产出只留三样**：一个段位、一个短板、一个下季度动作。多一个都算跑偏。

---

**两张表怎么配合用**：先填六环自检表，定位断点所在的那一环；再用四类能力自检表，看断点对应的是哪类能力弱。前者告诉你"哪儿断了"，后者告诉你"补什么"。

---

## 三、成熟度自评表（六维度 × 五级行为锚定）

**填法**：每个维度选一个最贴近的行为锚，不填形容词、只锚行为。产出仍是"一个段位、一个短板、一个下季度动作"。

| 维度 | L1 被动响应 | L2 单点应用 | L3 流程贯通 | L4 数据驱动 | L5 智能原生 | 你的档位 |
|---|---|---|---|---|---|---|
| 闭环完整性 | 断在哪没人知道 | 六环有人盯，但靠人 | 六环有 owner、有回流 | 断点自动现形 | 闭环自己越转越准 | |
| 根因定位力 | 归"态度问题" | 能下钻到现象 | 下钻到可改层 | 根因有数据佐证 | 定位反哺上游设计 | |
| 派单有效性 | 转派凭感觉 | 有分工但常绕圈 | 分对率可量化 | 绕圈自动拦截 | 派单策略自加权 | |
| 处理真实度 | 关单即结案 | 有处理但无验证 | 分层干预在跑 | 真解决率可测 | 处理知识回流 | |
| 验证闭环 | 从不回头看客户 | 偶尔抽查 | 验证成固定动作 | 感知指标同向监控 | 验证驱动策略 | |
| 评估科学性 | 写总结报告 | 有口径但不同框 | 三类同框、有对照 | 结论落资源分配 | 评估重塑下一轮 | |

**判读**：六个维度里最弱的那一档，决定闭环整体下限——补短板比堆长板便宜。五级不是打分排名，是给自己定"下一步往哪一级走"的台阶。

三条判读纪律（跟自己比不跟同行比／卡在相邻两级之间是常态／同一组织内不同链路可以不同段位）见本专家正文「成熟度自评」一节。

## 四、中型体量裁剪版自评（100–1000 人用）

**这份表给谁用**：方法论全套照搬太重、装了转不动的中型组织。第一至三份表是通用表，**本份是裁剪版**——只评最可能断的两三个维度，不评全。

### 第一步：定"主责一环"

**只填「有人回头看吗」这一列**，其余列留空。空得最多的那一环，就是这一轮要补的那一环。

| 环 | 有人"回头看"吗 | 断点判定 |
|---|---|---|
| 发现 | | |
| 定位 | | |
| 派单 | | |
| 处理 | | |
| 验证 | | |
| 评估 | | |

### 第二步：只评 2–3 个维度

按业务形态挑，**不必六个都评**：

| 业务形态 | 优先评哪 2–3 个维度 | 第一轮先不管 |
|---|---|---|
| B2C 高频交易 | 派单有效性 → 验证闭环 → 处理真实度 | 评估科学性（样本还不够） |
| B2B 长周期 | 派单有效性 → 根因定位力 → 验证闭环 | 闭环完整性、评估科学性 |
| 线下服务（门店、物业） | 根因定位力 → 验证闭环 → 闭环完整性 | 评估科学性 |
| 多品牌多门店 | 派单有效性 → 闭环完整性 → 验证闭环 | 根因定位力、评估科学性 |

对上第二步挑出的维度，照第三份「成熟度自评表」逐格比行为锚，填一个段位。

### 第三步：产出只留三样

| 产出 | 填什么 |
|---|---|
| **一个段位** | 第 X 环，<维度名> 维度 L__ |
| **一个短板** | 一句话：因为<一件具体的事> |
| **一个下季度动作** | 一个动作 / 一个主责人 / 什么算完成 / 何时看 |

### 裁剪纪律

1. **只补最弱的一环**，其余五环保持"有人、有动作"即可，不要求闭环。
2. **组织保障只做一件事**：每一环有且只有一个主责人。这条做到，六环就转得动；做不到，裁剪再多也白搭。
3. **答不出行为锚的维度写"没做过"**，不要折中打分——折中分等于没信息。
4. **这一轮不要做工具采购论证**。先跑出第一批事实，再谈系统。

## 五、大体系首问清单（1000 人以上用）

**这份表给谁用**：一线弃用工具、跨部门推不动的体系。**先治口径与责任单元，再谈闭环工具**——顺序反了，会推出一套更精致的无用系统。

### 第一步：口径分歧盘点

同一个指标，几个部门各给一个数？逐项填，差异根因写不出"是谁的算法"就写"没人对过口径"。

| 指标 | 客服口径 | 市场口径 | 平台口径 | 是否一致 | 差异根因 |
|---|---|---|---|---|---|
| 客户满意度 | | | | | |
| 投诉量 | | | | | |
| 首次响应时长 | | | | | |
| NPS | | | | | |
| 一次解决率 | | | | | |

### 第二步：责任单元唯一性检查

| 检查项 | 答得上吗 |
|---|---|
| 一个客户诉求进入体系的**唯一入口**是哪里？ | |
| 每个问题都有**唯一主责单元**吗？ | |
| 跨部门的事**归谁**？有没有争议处理机制？ | |
| 绕圈的工单**谁在看**？ | |
| 关单之后**谁**回头核客户感知？ | |
| 跨部门考核**归谁**？ | |

### 第三步：结论回流检查（多层级多地域必填）

| 检查项 | 答得上吗 |
|---|---|
| 班组的结论**能不能上到**地市一级？ | |
| 地市一级的判断**能不能回到**班组？ | |
| 下一轮盘点**用不用得上**上一轮的结论？ | |
| 一线打开系统之后**有没有新动作**？ | |

### 大体系纪律

1. **先治口径，再谈工具。** 第一步不通过，后面三步都别做。
2. **收敛触点**：一线只保留"必须记录"的最小集。宁可少，别让一线认定这是"上面要来的记录负担"——那是最快的弃用理由。
3. **判断层只给"先治哪一样"**。跨部门对齐、一手数据核证与对外正式报告需要真人承接，本表只负责把问题定位到具体那一样。

## 六、最小台账表头（轻量档用 · 一行一条）

**这份表给谁用**：没有专职岗、还报不出任何统计数据的团队。**它不是报表，是"攒事实"的容器**——先把第一批事实跑出来，报表是后面的事。

**为什么先给表头、而不是给一张空表**：空表会让人误以为"差数据而已"，于是把表丢在一边；**给表头 + 每列填法，是把"从今天开始记什么"这件事定死**。表头本身就是要求：**每条至少能回答那三件事**。

**最低要求：只填三列**（这三列合起来就够判断问题出在派单还是验证）：

| 进来时间 | 归谁（唯一主责） | 什么时候闭合 | 客户感知有没有变 | 重复来过吗 | 备注 |
|---|---|---|---|---|---|
|  |  |  |  |  |  |

**每列怎么填**：

| 列 | 填什么 | 填不出时怎么办 |
|---|---|---|
| **进来时间** | 客户第一次表达这件事的时间（不用精确到分，精确到天就行） | 记不住就写"本周内"，别空着 |
| **归谁（唯一主责）** | **一个名字**，不是部门；转过派的写最终接手的人 | 不知道写谁就写"没人认领"——**这本身就是断点证据** |
| **什么时候闭合** | 这件事最后一次有动作的时间；没闭合就留空 | 留空就行，别填"处理中" |
| **客户感知有没有变** | 闭合后有没有再核过一次客户（是／否／未核） | 没核就写"未核"，**不要写"应该解决了"** |
| **重复来过吗** | 同一客户、同一件事是不是又来了（是／否） | 只写你确定的；不确定就留空 |
| **备注** | 一句话：卡在哪、为什么没闭合 | —— |

**三条纪律**：

1. **一行一条事，不一行一个人**——同一个客户的两件不同的事，写两行。
2. **只记事实，不记评价**——"客户很生气"是评价，"客户第二次打来"是事实。
3. **先跑一周，再看**——**不要设计复杂表格**；一周之后只看一件事：**归谁那一列，有没有出现"没人认领"。**

**跑出来之后看什么**：如果"没人认领"和"未核"这两类反复出现，断点基本就在**派单**与**验证**两环——这时候再回到第一份六环自检表定位，然后才谈别的。

**别做的事**：不要一上来就设计完整报表字段、不要加编号规则、不要接系统。**轻量档的表越简单，越可能真的被记下去**——记不下去的表比没有表更坏，因为它会让人以为这件事已经在管了。

---

**六份表怎么配合用**：第一至三份是通用底座（先填六环自检表定位断点环，再用四类能力表看补什么，用成熟度自评读段位）；**先定体量档再选表**——判据见正文「按组织体量分档」与 `scale-tiering.md`（有没有专职岗，不看人数）：无专职岗用轻量三问先止血、并用第六份最小台账攒第一批事实；100–1000 人用第四份裁剪版；1000 人以上先用第五份治口径；**定档拿不准按正文的兜底纪律走**（默认轻量档起步）；**体量定完再回到第一至三份取用需要的表**。
