# 诊断报告模板（固定结构）

> 本文件配合本专家正文使用。用户要"出报告"、需要留档、要拿去内部开会时，按此结构交付。
> 正文只保留报告骨架与报告纪律，完整可复制模板在这里（完整版／汇报版／大纲视图版／HTML 可视化版 四种）。
> **按段名指认，不按段号**——本模板的段名见下表。要引用某一段，说段名（「结论」「断点」「归因」「短板」「停摆」「下一步」「待确认」「往下走」），不说第几段。

---

## 一、完整版（Markdown，直接复制填写）

```markdown

- 落差多大（感知−期望）：
- 差在哪（五差距）：Gap __
- 怎么证明（服务蓝图取三类指标）：

## 四、能力短板

| 能力 | 档位 | 依据 |
|---|---|---|

## 五、停摆测试

- 没有系统，工作方式还在吗：
- 结论：

## 六、下一步

| 动作 | 谁来做 | 什么算完成 | 何时看结果 |
|---|---|---|---|

## 七、待确认清单

- 需要你补充的数据 / 需要核实的口径：

## 八、往下走 · 三选一

- **① 自己先走**：拿十问自测表／六环自检表把这一环填一遍，不花钱，判断层就够，不用升级。
- **② 要做出来**：按「下一步」那一条的动作先自己起步——谁来做、什么算完成、何时看结果，本报告已给。手上已有能报出来的关键数、想拿自己的数据算，超出本技能范围；本层不代算。参数（阈值、字段、权重）仍不代填，需结合你们自己的数据定。
- **③ 要进系统、要团队对齐、要对外正式件**：需一手数据核证与跨部门对齐，超出本技能范围。

> **一句约定**：这一环动一动，通常要一两周才看得出变化。过一周左右想再对一次，随时回来，不用重新讲背景——哪怕只是发现推不动，也是个结论。
```

## 二、汇报版（分层精简，贴 PPT 用）

每段压到三行以内，一级标题＝页码，二级要点 ≤ 3 条，去掉表格与纪律说明。

```markdown
## 1 结论
断在 <第 N 环>；先做 <一个动作>；暂不做 <一件事>。

## 2 断点
<环>：<一句证据>。边界：<一句提醒>。

## 3 归因
落差 <感知−期望>；差在 Gap <N>；证据 <三类指标哪一类>。

## 4 短板
<能力>：<档位>，因为 <一件具体的事>。

## 5 停摆
没有系统还在吗：<在 / 不在>。

## 6 下一步
<动作> / <谁> / <什么算完成> / <何时看>。

## 7 待确认
<缺的数据>。

## 8 往下走
三选一：自检表自己走／按「下一步」自己排动作／要进系统 → 超出本技能范围。

一句约定：过一周左右想再对一次，随时回来，不用重讲背景。
```

## 三、大纲视图版（贴 PPT · 思维导图工具 · 一眼看全局）

> 这一档给"贴进 PPT／导进思维导图工具"用：**纯缩进层级，没有表格、没有符号装饰、没有正文段落**。粘进 XMind / MindMaster / 幕布 等工具，缩进层级会被自动识别成树；粘进 PPT，用"转换为 SmartArt"或标题层级即可。

### 3.1 完整大纲（同一套结构，缩进即层级）

```text
客户体验断点诊断
├─ 结论
│  ├─ 断在：<第 N 环>
│  ├─ 依据：<一句话证据>
│  ├─ 首要动作：<一个动作>
│  └─ 暂不建议做：<一件事>
├─ 断点定位
│  ├─ 发现环：<判断>
│  ├─ 定位环：<判断>
│  ├─ 派单环：<判断>
│  ├─ 处理环：<判断>
│  ├─ 验证环：<判断>
│  └─ 评估环：<判断>
├─ 归因（三底座）
│  ├─ 感知−期望落差：<多大>
│  ├─ 五差距定位：Gap <N>
│  └─ 证明方式：<运营/体验/KPI>
├─ 能力短板
│  ├─ 全面感知：<档位>
│  ├─ 智能研判：<档位>
│  ├─ 高效处置：<档位>
│  └─ 有效评估：<档位>
├─ 停摆测试
│  ├─ 没有系统，工作方式还在吗：<在/不在>
│  └─ 结论：<一句话>
├─ 下一步
│  ├─ 动作：<做什么>
│  ├─ 负责人：<谁>
│  ├─ 完成标准：<什么算完成>
│  └─ 何时看结果：<时间>
├─ 待确认清单
│  ├─ <缺的数据或口径 1>
│  └─ <缺的数据或口径 2>
└─ 往下走
   ├─ 自己先走 → 自检表
   ├─ 要做出来 → 按「下一步」自己排动作
   └─ 要进系统 → 超出本技能范围
```

> **大纲树节点之间不留空行**，末级分支统一用三个空格缩进；夹了空行或缩进不齐，粘进工具会断树。

### 3.2 精简大纲（只有三支，贴 PPT 首页用）

> 汇报材料通常只要"断在哪、先做什么、别做什么"。这一档压到**一棵三层的树**。

```text
客户体验断点诊断
├─ 断在：<第 N 环>（<一句话证据>）
├─ 先做：<一个动作>（<谁> · <何时看结果>）
└─ 先别做：<一件事>
```

### 3.3 使用纪律

1. **这一档只画结构，不装内容**——每格只放**一句**，不放段落、不放表格。**它的作用是让人在 10 秒内看懂"断在哪、接下来走哪条路"**；
2. **断点环要标出来**——在「断点定位」那一支里，**把断的那一环标出来**（如在环名后加 `← 断点`）。六环平铺看不出断点，等于没画；
3. **不编数**——层级里出现的一切数值都是用户给的真数，**没给就留空或写"待确认"**；
4. **同一套纪律**：不编数、结论带依据、待确认清单不可省、出口段不可省——**换成缩进不等于可以省**；
5. **思维导图工具的导入**：直接粘贴上面的 `├─ └─ │` 缩进文本，多数工具（XMind / MindMaster / 幕布 / ProcessOn）会自动转成树状图；**若不识别，就用带缩进的行首空格重排一遍再粘**。

## 四、可视化版（HTML 单文件）

要发邮件、贴内网、给不看 Markdown 的管理层时用。生成一份**自包含单文件 HTML**：样式内联、无外部依赖、双击即开、可整份转发。

结构照同一套走，用视觉层级代替段落堆叠：

- **顶部**：一行结论卡（断在第几环 / 首要动作 / 暂不做），字号最大
- **断点**：六环横向色块，断的那一环标红，其余标灰
- **归因**：落差与 Gap 用两行短句，不画虚假精确的图
- **短板**：四类能力四格，弱的那格标红
- **停摆**：一句话独立成块
- **下一步**：表格式三列（动作 / 谁 / 什么算完成）
- **待确认**：清单
- **往下走**：同完整版「往下走」那段文字

**硬约束**（违反即算编数）：

1. **不生成图表数据。** 没有真实数值就不画柱状图、不画趋势线、不标百分比——视觉可以只用色块与文字层级。
2. **样式内联，不引 CDN。** 单文件必须能离线打开、能直接进内网邮件。
3. **打印友好。** 适配 A4 宽度，黑白打印下断点仍可辨（不靠颜色单独承载信息，配文字标注）。
4. **不编数、不承诺结果**——与 Markdown 版同一套报告纪律。

## 报告纪律（四种形态通用）

1. **不编数**。用户没给的数据一律写进「待确认清单」，**不用行业经验值替代**——那正是分层纪律要防的事。
2. **结论必须带依据**。每个判断后面跟一句"因为……"，没有依据的判断不写。
3. **待确认清单不可省**。哪怕这次判断看起来很清楚，也要列出"这个结论依赖哪些我没拿到的数据"。
4. **只给判断层**。报告里可以写"该看哪类指标"，**不写具体阈值、字段清单、权重**。
5. **不承诺结果**。不写"这样做满意度能提升 X%"，写"可观察的指标：……"。
6. **「往下走」那一段不可省，且必须是「三选一」＋「一句约定」**。它是报告的出口——告诉用户往哪走、要不要自己接着做、要不要找人工，并给一个不打扰的复访理由；省了，报告就断在那儿，前面所有判断白做。

> **示意样张与出口段的关系**：`references/report-samples.md` 是脱敏示意（数值留空、标注「这是一份示意，不是你的诊断结果」），**示意 ≠ 交付**；正式出具仍按本模板走，「往下走」那一段的三选一与「一句约定」不可省。
