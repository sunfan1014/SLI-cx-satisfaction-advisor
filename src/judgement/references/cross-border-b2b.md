# 外贸 / 跨境 B2B 场景（跨境特有断点 · 判断层）

> 本文件配合本专家正文使用。**这是「按需引用」的场景档**：用户是出口/外贸/跨境业务（或明确提到跨时区、多语言、国际物流、海外仓、境外客服）时再打开。
> 通用六环框架见正文；本文件只补**跨境特有的断点与判别**。
> 按组织体量选打法见 `references/scale-tiering.md`；十问自测表见 `references/ten-question-selfcheck.md`。

## 一、跨境场景为什么常被通用框架误诊

通用六环在跨境场景**大部分仍然成立**，但有三处会**误判**——因为"客户体验"在这个场景里的对象变了：

| 通用框架的默认假设 | 跨境场景的实际情况 | 误判后果 |
|---|---|---|
| 投诉量 ≈ 问题总量 | 跨境客户的**沉默成本极高**——海外客户遇到问题多半直接换供应商，不投诉 | **把"投诉少"读成"体验好"**，实际是在流失 |
| 满意度可横向比较 | B2B 跨境**单子少、金额大、决策人不在你这边**，一个客户一年就几单 | 用 B2C 的 NPS 逻辑判断，**统计意义不成立**（样本量根本不够） |
| 客户感知你能影响 | 客户感知到的体验**大部分不在你这**：交期由船期定、价格由汇率与原材料定、时效由清关定 | 把不可控项当成你的闭环环，**六环全打上"断"却无从下手** |

**这一层的判断原则**：**先分清哪些环节的体验真在你手里，再谈断点**。不是每个"客户不满"都是你的闭环问题——**先做一次"可控性切分"**。

---

## 二、可控性切分（跨境场景第一步，先做这个）

把客户旅程上的每个触点归到三类：

| 类别 | 含义 | 你的动作 |
|---|---|---|
| **完全可控** | 你能直接决定结果（如：回复时效、报价响应速度、单证准确性、异常沟通的频次与诚意） | **这一类才是你的闭环范围**，断点在这类里找 |
| **部分可控** | 你能影响但不能决定（如：交期承诺、赔付方案审批、物流异常的处理） | **改"承诺与预期"，不改结果**——见「期望管理是跨境的第一杠杆」 |
| **不可控** | 你完全说了不算（船期、汇率、政策、清关查验） | **只做一件事：提前告知与解释**，别承诺控制不了的事 |

> **这一条是跨境场景最重要的判断**：**很多"客户体验差"最终查出来是"承诺了不可控的事"**。这类问题在通用框架里会被误判成"发现/定位环断了"，实际是**期望管理缺口**——**别在闭环上使劲，要在承诺上使劲**。

## 三、跨境特有的四类断点（按发生频次排）

### 1. 交期承诺与实际不符（最高频，也最伤）

**典型形态**：销售为了签单报了偏乐观的交期（把船期/清关的正常波动当成了确定值），客户按这个安排了自己的下游，货物晚到 → 客户不满，但**你的闭环六环全绿**——因为你的内部流程确实都走完了。

**判断层要点**：
- **交期承诺前有没有区分"确定项"与"浮动项"**——这是发现环的问题（信号采集时就没区分）；
- **客户感知到的交期是销售承诺的那个数，还是实际到港的那个数**——如果两者不一致，断点在**期望塑造**（前端承诺），不在履约；
- **承诺超出可控范围时，有没有对客户做过一次显式的风险提示**——没有，风险告知缺失就是发现环的断点。

**判别问句**："你们的交期承诺里，**哪些部分是你们能保证的**？客户知不知道哪部分会浮动？"

### 2. 时区与响应窗口（最容易被忽视）

**典型形态**：客户在北美，周五下午发来一封询盘；你的团队在上海，周一上午才回。**从客户视角看是"放了两天"，从内部看是"周末没上班"**——但客户不会为你的时区做解释。

**判断层要点**：
- **响应时效的度量基准是"客户当地时间"还是"我方工作时间"**——这两者不一致，就是一个隐形的体验差；
- **有没有覆盖客户活跃时段的轮值安排**——没有的话，"响应慢"是**派单环**的常态断点；
- **时区差是"运营事实"还是"沟通话术"**——如果对客户说"这是时区问题"，那是把责任推给客观条件，**正确做法是给一个可预期的承诺**（如"24 小时内必回"）。

**判别问句**："客户在你们的**下班时间**提的问题，多久能收到第一次回应？这个时间是从**谁的时间**算起？"

### 3. 多语言沟通的信息损耗

**典型形态**：技术图纸、验收标准、投诉描述在跨语言传递中丢失关键约束；客服用翻译软件回复，客户感受到的是"他没听懂"。

**判断层要点**：
- **关键约束（规格、交期、验收口径、责任划分）有没有留在原文里**——全靠口头/即时通讯传递的，**跨语言必丢**；
- **多语言版本的"标准承诺"是否一致**——同一句承诺的不同语言版本含义不同，是**期望管理缺口**；
- **是否明确"以哪个文本为准"**——合同/邮件/聊天记录三个版本冲突时，客户会挑对自己有利的那个解释。

**判别问句**："客户收到的**正式确认**是中文还是外文？关键约束**有没有一份他看得懂的书面版本**？"

### 4. 国际物流异常的处理（断在"处理"与"验证"之间）

**典型形态**：货损、错发、清关查验滞留；一线按流程赔付/补发 → 事情"处理完了"，但**没有人回头确认客户的下游有没有因此停摆**（客户的客户在等他的货）。

**判断层要点**：
- **异常处理完，谁回头确认"客户的业务有没有被这次异常影响"**——这正是验证环，跨境场景里**这一环比国内场景更空白**，因为"客户的下游"不在你的视野里；
- **异常的信息是否回流到发现环**（这一类异常会不会重复发生）；
- **承诺的补偿与实际的恢复节奏是否对得上**——赔付很快但补货很慢，客户的感知仍是"没解决"。

**判别问句**："上个月那几次物流异常，**处理完之后有人问过客户'您那边的业务受影响了吗'吗**？"

## 四、跨境场景的判别补充（补进六环）

在通用六环之外，跨境场景额外要看的三问：

| 环 | 通用问法 | 跨境追加问法 |
|---|---|---|
| **发现** | 不满信号有几种来源？ | 客户**沉默流失**的信号怎么采集？（询盘量骤减、重复询价消失、订单量下滑） |
| **定位** | 现象下钻到哪一层？ | 这个问题是**你可控的**，还是**承诺/外部造成的**？ |
| **派单** | 谁来负责、多久闭环？ | 跨时区跨语种的响应时效，**从客户当地时间算**由谁兜底？ |
| **处理** | 一线真的解决了吗？ | 处理动作**是否以客户能看懂的语言、书面形式留下**了？ |
| **验证** | 有没有回头核客户感知？ | 异常处理后，**有没有确认客户的下游业务没被卡住**？ |
| **评估** | 结论送回发现了吗？ | 同一类异常**三个月后还在重复吗**（如同一航线的同一类货损）？ |

## 五、NPS 在跨境 B2B 的适用性（评委明确点出的坑）

**结论先给**：**B2B 跨境低频大额场景里，NPS 统计意义有限，不建议作为主指标**。

| 原因 | 说明 |
|---|---|
| **样本量不足** | 大客户一年就几单，回复率天然低，几十份答卷算出的分数**没有代表性**； |
| **决策人不在你这边** | 使用者和评价者常不是同一个人，答卷反映的是**某个人的偏好**而非组织体验； |
| **关系抬高了分数** | 长期合作方倾向于给高分（不想失去供货关系），**分数会虚高**； |
| **周期不匹配** | 一次交付周期可能跨数月，"体验"落在哪个时点说不清。 |

**替代做法（判断层给方向，不给阈值）**：

1. **主指标换成过程事实**——响应时效达成率、异常闭环率、**承诺与实际的偏差次数**（这一项跨境场景最贴切）；
2. **评价对象换成"客户的下游"**——问客户的客户有没有被卡住，比问客户满不满意更能反映真实体验；
3. **用事件复盘替代打分**——每次重大异常做一次结构化复盘（发生了什么、承诺差多少、谁受影响、下次怎么防），**比一个总分有用得多**。

> **不要因为"书上都写 NPS"就硬上**。这一层给的是"该不该用、为什么、拿什么替代"——**分值口径属于执行层，需结合企业自己的历史分布确定**。

### 低频大额／专业服务形态（不限跨境）

上面讲的不只是外贸：大客户、专业服务、学术推广一类「单子少、金额大、决策链长」的场景，同样不适用满意度打分与样本推断，但**仍可用五差距做定性归因**——尤其 Gap 4 沟通差距，用来看「承诺了什么／实际交付了什么」。

这一形态改看三条过程事实（判断层只给判据，不给权重与模板）：

1. **逐事件的承诺—交付偏差**代替满意度分数：记录承诺了什么、实际交付了什么、差在哪；

2. **使用者／评价者／决策者分别回核**：三者常不是同一人，各问一次，不合并成一个分；

3. **用结构化事件复盘代替打分**：发生了什么、承诺差多少、谁受影响、下次怎么防。

> **边界**：这一层不补行业模板、品类权重、拜访或跟进动作清单；超出本技能范围。六环仍可逐环映射，先做可控性切分再判断点。

## 六、AI / 数智化选型在跨境场景的注意点（不绑工具，只给判据）

评委提到"外贸企业常用沟通工具的集成场景"——**这一层不做工具推荐、不谈集成方案**，只给三条判断：

1. **先看数据在哪、再谈用什么**——客户沟通、订单、单证、异常记录往往分散在**不同系统与不同语言环境**里；**"数据能不能汇到一处"是选型的第一前提**，不是模型能力；
2. **多语言场景里，"翻译准确"不是选型标准**——真正要问的是：**关键约束（规格、交期、责任）有没有结构化字段**，翻译只是表层；
3. **跨时区的自动化边界**：**触发条件按客户当地时间设**、**执行动作在客户预期窗口内落地**，这两条不定，自动化只会放大差评。

## 七、这一层的边界（不给什么）

| 不给 | 为什么 |
|---|---|
| 不给**跨境合同条款/贸易术语/合规清单** | 属法律与贸易合规专业范畴，有专门规定 |
| 不判断**目的国法规**（数据出境、消费者保护、产品认证） | 各国差异大且会变，须由有资质方按最新法规确认 |
| 不给**汇率、关税、清关时效**的具体判断 | 这些是外部变量，需查当期官方口径，**判断层不报数** |
| 不给**跨国团队组织设计** | 属组织管理范畴，且个案差异极大 |

**这一层仍然能给的四件事**：① 可控性切分（哪些环节真在你手里）；② 跨境四类特有断点的判别；③ NPS 适用性判断与替代指标方向；④ 期望管理的具体做法（**承诺区分确定项与浮动项**）。
